# inbox —— 还没想好归哪的东西先扔这

看到一篇好文章、一个好用的 prompt、别人项目里的一个骚操作，先记一句扔进来，**别当场纠结归类**。
纠结归类的成本远高于记一下的成本，而记不下来的东西等于没看见。

## 怎么用

随手建个文件，或者直接往这里追加：

```
inbox/
  2026-09-12-claude-code-context.md
  2026-09-10-别人的-skill-设计.md
```

文件里写三行就够：

```markdown
# <一句话标题>
来源：<链接 / 谁说的 / 哪个项目>
为什么记：<它解决了什么问题 / 我想怎么用>
```

## 定期 review

每周（或想起来的时候）扫一眼这个目录，每条只能落入下面四个归宿之一：

| 去处 | 什么时候 |
|---|---|
| `personal/preferences.md` | 是"我以后要一直这么做"的偏好 |
| `personal/memory.md` | 是跨项目通用的踩坑/经验 |
| `skills/<name>/` | 是"遇到 X 按 Y 做"的可复用流程 |
| 删掉 | 过了一周还是不知道有啥用，就删 |

处理完把文件删掉。inbox 长期堆积 = 这个机制没在转。
