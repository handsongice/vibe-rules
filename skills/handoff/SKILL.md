# 跨会话交接

## 触发条件

- 用户明确说"换 agent"、"重开"、"接着之前的干"
- 当前会话上下文快满了
- 你（agent）要从 qoder 切到 codex、从 trae 切到 claude 之类

## 铁律

> **不要复述已有产物。** 项目根有 AGENTS.md、docs/specs/、docs/plans/、git 历史、commit、diff——这些下一个 agent 自己会读。你只写**它们之间没有的东西**：现在卡在哪、为什么卡、下一步干什么。

## 交接文档放哪

写到系统临时目录或项目里 `docs/handoffs/YYYY-MM-DD-<topic>.md`，**不要**污染项目根。文档里用相对路径引用已有产物。

## 必须包含的 6 段

```markdown
# Handoff: <一句话主题>

## 现在在哪
- 已完成：<列 3-5 条，带 commit 或文件路径>
- 进行中：<具体到哪个文件、哪一行、为什么停>
- 卡住的点：<如果有，说清楚试过什么、为什么不行>

## 下一步
<下一个 agent 第一件事应该做什么。一条就够，不要列计划。>

## 上下文
- 关键文件：<只列下一个 agent 必须立刻读的，其他让它自己 grep>
- 关键决策：<口头达成但没写进 spec 的决定，按重要性排>
- 坑：<这个任务过程中踩到的、下一个 agent 容易再踩的>

## 推荐先调用的 skill
<按顺序：比如 systematic-debugging → tdd → pre-commit-check>

## 已脱敏
<列出你检查过的敏感项：API key、token、PII 都没写进本文档>
```

## 不要做

- 不要把 AGENTS.md 内容抄一遍。
- 不要把 spec/plan 抄一遍，给路径就行。
- 不要写"我们讨论了很多"、"这个项目很复杂"这种废话。
- 不要把密钥、密码、用户个人信息写进来。
- 不要假设下一个 agent 知道你上一个会话说过什么——口头共识要写出来。

## 反面：下一个 agent 接到交接时

1. 先读本文件
2. 按"推荐 skill"顺序调用
3. 按"下一步"开始，不要重新质疑已经做过的决策（除非发现明显错）
4. 如果交接文档和实际代码不符，以代码为准，并在新交接里指出
